# ARENA Maintenance Runbook

Single index of periodic operational tasks for an ARENA deployment (production or staging). It applies to any instance run from this repo; examples use the paths this repo's scripts create. Setup-from-scratch is covered in [README.md](README.md).

Instance-specific infrastructure — offsite sync targets, monitoring endpoints, internal contacts — belongs in your organization's own private ops notes, not in this file.

Related tracking issues from the 2026-08 credential security review: [#51](https://github.com/arenaxr/arena-services-docker/issues/51)–[#58](https://github.com/arenaxr/arena-services-docker/issues/58).

## Maintenance calendar

### Automated (verify monthly — see checks below)

| Task | Mechanism | Where |
|---|---|---|
| TLS cert renewal (main stack) | certbot container runs `renew` every 12h; nginx reloads every 6h | `docker-compose.prod.yaml` |
| Broker cert pickup | mosquitto restarts every 720h to load renewed certs | `docker-compose.yaml` |
| Jitsi TLS renewal | acme.sh cron in the Jitsi web container (**only after** the `jitsi-add.sh` webroot fix — see [README → Fix Jitsi certificate renewal](README.md)) | `jitsi-add.sh`; log: `${JITSI_CONFIG}/web/acme.sh/acme-cron.log` |
| MongoDB backup | root crontab, e.g. daily 01:00: `backup.sh` → `data/backup/$HOSTNAME` (set this up if you haven't: `sudo crontab -e`) | `backup.sh` |
| Offsite backup sync | If you replicate `data/backup/` (and the store) offsite — recommended — schedule it in cron and note the target in your private ops docs | your crontab |

### Monthly

- **Verify the automation above ran**:
  - Certs: `echo | openssl s_client -connect $HOSTNAME:443 2>/dev/null | openssl x509 -noout -enddate` (repeat for the Jitsi host). Expect >30 days remaining.
  - Backups: newest dump in `data/backup/$HOSTNAME` is <24h old; offsite copy (if configured) matches.
  - Jitsi renewal log has a recent successful run.
- Disk space and container health: `df -h`, `docker ps` (nothing restart-looping), Grafana dashboards load and show data.
- Review deploy/token notifications in the Slack channel wired to `SLACK_DEV_CHANNEL_WEBHOOK` (if configured) for anything unexpected.
- Dependency PRs (dependabot/release-please) triaged across the arenaxr repos.

### Quarterly

- **Service/CLI MQTT token expiry check** (they all expire together, 365 days after the last `init-config.sh` secrets run — currently there is no other warning except arena-persist's startup log):

  ```bash
  # print expiry of every service token in secret.env + the CLI token
  for t in $(grep -oE 'ey[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+\.[A-Za-z0-9_-]+' secret.env data/keys/cli_token.json); do
    python3 -c "import base64,json,sys,datetime; p='$t'.split('.')[1]; p+='='*(-len(p)%4); c=json.loads(base64.urlsafe_b64decode(p)); print(c.get('sub'), datetime.datetime.utcfromtimestamp(c['exp']))"
  done | sort -u
  ```

  If any expiry is <90 days out, run the **service token rotation** procedure below at the next maintenance window.
- Google Cloud console review for your OAuth project: Essential Contacts current; billing/budget anomaly alerts enabled and routed; OAuth clients — redirect URIs/origins restricted to expected values, no unrecognized clients or grants.
- Backup **restore drill** (quarterly, not just existence check): restore the latest dump into a scratch container — `docker run --rm -v $PWD/data/backup/$HOSTNAME:/dump mongo:latest bash -c "mongod --fork --logpath /tmp/m.log && mongorestore /dump && mongosh --quiet --eval 'db.getSiblingDB(\"arena_persist\").arenaobjects.countDocuments()'"` — and sanity-check the count.
- Review open `security`-labeled issues across the arenaxr repos; re-prioritize.

### Annual (or on suspected compromise / personnel change — then do it immediately)

| Credential | Procedure | Notes |
|---|---|---|
| MQTT service + CLI tokens | Rotation procedure below | Expire on their own at 365d — rotate *before* expiry, on your schedule, not the token's |
| JWT RSA signing keypair | Rotation procedure below | **Flag day**: invalidates every outstanding token (incl. user device tokens) until [#55](https://github.com/arenaxr/arena-services-docker/issues/55) lands — schedule a maintenance window |
| Google OAuth client secrets (web + installed + device) | Rotation procedure below | Also rotate immediately if a secret was ever committed/pasted anywhere |
| `DJANGO_SUPERUSER_PASSWORD`, `STORE_ADMIN_PASSWORD`, `SECRET_KEY` | Regenerated by the secrets step of `init-config.sh` | Rotating `SECRET_KEY` changes derived filestore passwords — plan a filestore password resync |
| Slack webhook (`SLACK_DEV_CHANNEL_WEBHOOK`) | Regenerate in Slack app config; update `.env` | Rotate on any team departure |
| Review | Re-run a credential/security review; update this runbook | Last full review: 2026-08-31 |

## Rotation procedures

> After **any** secret/key/token change: regenerate configs and restart the stack — configs are rendered from templates at init time and mounted read-only. See the warning in [README.md → Init Config](README.md).

### Rotate MQTT service tokens (no flag day — signing key unchanged)

1. `./prod.sh down` (or `staging.sh`).
2. `./init.sh` → answer **N** to new secrets, **N** to new keypair, **Y** to regenerate service tokens (prompt in `init-config.sh`).
3. Until [#51](https://github.com/arenaxr/arena-services-docker/issues/51) lands: `chmod 600 secret.env data/keys/cli_token.json` and remove `secret.tmp` / `secret.env.bak` (the `.bak` holds the *previous, still-valid* tokens).
4. `./prod.sh up -d`; confirm arena-persist's startup log shows the new expiry and no CRITICAL token warning.
5. Distribute the new CLI token to whoever needs it **by direct secure channel — never chat/webhook**.

### Rotate the JWT signing keypair (flag day)

1. Announce a maintenance window: all user sessions, device tokens, and service tokens become invalid.
2. `./prod.sh down`; `./init.sh` → **Y** to regenerate the root keypair; this also forces regenerating all service tokens.
3. `./prod.sh up -d`. Verify: web sign-in works end-to-end; `mosquitto_sub` with a fresh token connects; persist/recorder logs clean.
4. Users with long-term device tokens (arena-py/arena-unity headless) must mint new ones from their web profile.

### Rotate Google OAuth client secrets

1. Google Cloud console → APIs & Services → Credentials → for each client (web / desktop / TV-limited-input): add a new secret, note it, keep the old one active for the switchover.
2. Update `GAUTH_CLIENTSECRET`, `GAUTH_INSTALLED_CLIENTSECRET`, `GAUTH_DEVICE_CLIENTSECRET` in the env files; `./init.sh -c` to re-render configs (this refreshes the served `conf/gauth*.json`); restart the stack.
3. Verify web Google sign-in, then an `arena-py` interactive login (it fetches the fresh `gauth.json`).
4. Delete the old secret versions in the console. Remove any stale `gauth*.json.bak` from `conf/prod/arena-web-conf/` ([#56](https://github.com/arenaxr/arena-services-docker/issues/56)).

### Renew TLS out of band

- Main stack: `./init.sh -r` (stack must be **up**).
- Jitsi: after any Jitsi upgrade, re-run `sudo ./jitsi-add.sh` ([README → Fix Jitsi certificate renewal](README.md)) or renewal silently breaks ~60 days later; check `${JITSI_CONFIG}/web/acme.sh/acme-cron.log`.
